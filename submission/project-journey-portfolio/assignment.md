# Project Journey Portfolio

## Exercise Prompt

Submit one PDF as a group.

This exercise asks for a structured account of your project journey from first idea to tested prototype or product.

The goal is **not** to submit a long report. The goal is to show the most important steps in the journey in a way that makes sense for your project: short answers, clear structure, and concrete evidence.

Your portfolio should make visible how your group moved through the core stages of the course:

- starting from an initial project idea
- defining the problem
- discovering and reaching users
- proposing a solution
- building a prototype or product
- testing with users
- iterating based on feedback
- reflecting on meaning and next steps

For each important step, use the following logic:

- **What?** What happened? What was done, decided, built, tested, or changed?
- **So what?** Why did it matter? What was learned? What did it reveal about the users, the problem, or the solution?
- **Now what?** What followed from this? What changed in the project? What would be the next meaningful step?

The portfolio should not simply list activities. It should explain the logic of the journey: how the initial project idea was checked, how users were discovered afterwards, how user understanding shaped or changed the problem and solution, how testing produced feedback, and how feedback led to iteration or future plans.

Suggested length: **4-6 pages**, excluding appendix.

---

## 1. Initial Project Idea

### What?

Describe the project idea your group started with.

Include:

- initial project idea
- motivation for choosing it
- initial assumptions
- first problem idea
- expected target group or context
- early proposal, sketch, user story, or usage scenario

### Evidence

Include relevant evidence, for example early notes, sketches, proposal slides, first user stories, or assumptions collected during the first phase.

### So what?

Why did this project idea seem relevant or promising at the beginning?

### Now what?

What needed to be checked or clarified next?

---

## 2. Discovering and Understanding Users

### What?

Describe how you moved from the initial project idea to identifying, reaching, and understanding relevant users.

Include:

- users or user groups discovered
- users or user groups selected for interviews or tests
- how users were reached
- interview or research approach
- main insights from users
- persona, user segment, or user story

### Evidence

Include interview summaries, short user quotes, contact channels, notes, personas, user stories, or other evidence of user research.

### So what?

What did you learn about your users that could not have been known from the initial idea alone?

### Now what?

How did this user understanding influence the problem definition or solution direction?

---

## 3. Defining the Problem

### What?

Describe how the problem definition changed after checking the initial idea and learning more about users.

Include:

- initial problem definition
- refined or final problem definition
- assumptions that changed
- rationale for changes
- fit between users, context, and problem

### Evidence

Add evidence that supports the change from initial idea to refined problem.

### So what?

Why was the refined problem definition better or more useful than the initial one?

### Now what?

How did the refined problem definition shape the proposed solution?

---

## 4. Proposing a Solution

### What?

Describe the proposed solution and why it fits the problem.

Include:

- solution concept
- value proposition
- alternatives considered
- feature prioritization
- fit between users, problem, and proposed solution

### Evidence

Include sketches, decision notes, feature lists, user stories, or other relevant artifacts.

### So what?

Why was this solution direction chosen?

### Now what?

How did the proposal guide what was built or prototyped?

---

## 5. Building

The product or prototype itself is submitted separately in the Product Artifact ZIP.

In this section, only refer to that ZIP submission. There is no need to repeat screenshots, code, walkthroughs, or product details that are already included there.

Optionally add any short context that helps connect the artifact to the journey, if it is not already clear from the ZIP file.

---

## 6. Testing

### What?

Describe how the prototype or proposed solution was tested.

Include:

- what was tested
- who tested it
- how the test was conducted
- main feedback
- problems, surprises, or confirmations

### Evidence

Include test notes, user feedback, short quotes, observations, or summarized findings.

### So what?

What did user feedback reveal about the proposed solution?

### Now what?

What changed or should change based on the feedback?

---

## 7. Iteration and Next Steps

### What?

Describe how the project changed after feedback and what should happen next.

Include:

- changes made based on feedback
- changes planned but not yet implemented
- remaining limitations
- distribution, access, or shipping strategy
- maintenance or handover strategy
- possible role of AI in maintaining, adapting, or evolving the project

### Evidence

Include before/after comparisons, revised feature lists, next-step plans, or maintenance ideas.

### So what?

What is the most important learning from the iteration?

### Now what?

What would be the next meaningful step if the project continued?

---

## Submission Checklist

Before submitting, check that the portfolio includes:

- the first problem idea
- the initial project idea or proposal
- the relevant users or user groups
- the initial and refined problem definitions
- the proposed solution and value proposition
- a high-level description of the prototype or product
- user testing and feedback
- iteration or planned changes
- shipping, access, distribution, or maintenance strategy
- concrete evidence rather than only general claims
- a clear and concise structure
